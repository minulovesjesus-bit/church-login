# Church Attendance UI Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the inconsistent browser-default and legacy-styled surfaces with the approved responsive church-community design system while preserving every existing route, API contract, authorization rule, and interaction.

**Architecture:** Keep the existing Next.js App Router route files and domain state machines, introduce official shadcn/ui source components plus semantic Tailwind v4 tokens, and compose four shared shells for auth, student, staff, and kiosk surfaces. Migrate one route family at a time, retain test-bound compatibility classes until final cleanup, and verify the four approved concepts against deterministic browser renders.

**Tech Stack:** Next.js 16.3.1 App Router, React 19.2.8, TypeScript 6, Tailwind CSS 4.3.3, shadcn 4.19.0 with Radix primitives and Lucide icons, Noto Sans KR through `next/font`, Vitest, Testing Library, Playwright, `@axe-core/playwright`, Browser/IAB

**Spec:** `docs/superpowers/specs/2026-08-22-church-attendance-ui-design.md`

## Global Constraints

- Preserve every current URL, FastAPI endpoint, Supabase flow, DTO, role check, QR duration, and business rule.
- Use one code-native `십자가 + 열린 문` SVG brand mark; do not crop a logo from a concept PNG.
- Generate a standalone open-door/natural-light auth image; do not crop the flattened auth concept.
- Use real DTO fields. Student greeting remains `반가워요!`; teacher metrics remain `오늘 출석`, `현재 입실`, `이번 주`, `통계 대상`; recent attendance remains a scan-event list.
- Keep the approved palette: `#FFFFFF`, `#202521`, `#173D2B`, `#E9F0EA`, `#667169`, `#D8E1DA`, decorative `#C9A75B`, and readable gold foreground `#74561B`.
- All focus indicators must reach 3:1 adjacent contrast on white and sage surfaces. All interactive targets must be at least 44×44px.
- Use shadcn semantic tokens and built-in variants. Do not add raw page-level color overrides.
- Keep exactly one accessible student navigation and one accessible teacher navigation at a time.
- Preserve `.attendance-desktop-only` and `.admin-status` as test compatibility classes.
- Preserve simultaneous desktop/mobile attendance and student-list markup until the existing tests and hydration contract are intentionally replaced.
- Preserve existing accessible labels, status/alert roles, table/list semantics, `<time dateTime>`, captions, exact action names, cancellation behavior, duplicate-action locks, and camera cleanup.
- Remove English eyebrow labels. Do not implement concept-only notification, profile, fake metric, grade, paired attendance, or sidebar-collapse controls.
- Use `Sheet` or `Dialog` for modal surfaces so focus enters, traps, closes on Escape, and returns to its opener.
- Start the desktop breakpoint at exactly `64rem` (1024px).
- Normalize fidelity captures to 1440×900 for auth/teacher, 390×844 for student, and 1024×768 for kiosk.
- Run frontend commands with `/opt/homebrew/opt/node@24/bin` first in `PATH`; do not change the existing `package.json` Node engine as part of this UI plan.
- Do not modify route handlers, API clients, Supabase helpers, backend code, migrations, QR decoders, attendance DTOs, dashboard polling, or Seoul-time utilities.

## File Structure

### Design system foundation

- `components.json`: shadcn Radix/Nova project settings and aliases.
- `src/lib/utils.ts`: `cn()` class-merging helper generated by shadcn.
- `src/components/ui/*`: official shadcn source components used by the app.
- `src/components/brand/brand-mark.tsx`: canonical cross/open-door SVG and wordmark.
- `src/components/layout/auth-shell.tsx`: responsive auth image/form shell.
- `src/components/layout/student-shell.tsx`: student content and navigation frame.
- `src/components/layout/staff-shell.tsx`: shared teacher/admin frame.
- `src/components/layout/kiosk-shell.tsx`: locked/unlocked kiosk frame.
- `public/images/auth-open-door.png`: standalone implementation image matching the accepted auth concept.
- `src/app/globals.css`: Tailwind v4 semantic tokens, global typography, compatibility rules, and slice-by-slice legacy CSS removal.
- `src/app/layout.tsx`: Noto Sans KR and global toaster.

### Route slices

- `src/app/page.tsx`, `src/app/auth/*/page.tsx`, `src/app/onboarding/page.tsx`, `src/app/teacher/login/page.tsx`, `src/app/teacher/apply/page.tsx`: auth family.
- `src/app/student/*`, `src/components/navigation/student-navigation.tsx`, `src/features/attendance/*`, `src/features/events/*`: student family.
- `src/app/teacher/*`, `src/app/admin/layout.tsx`, `src/components/navigation/teacher-navigation.tsx`, `src/features/dashboard/*`, `src/features/students/*`: staff family.
- `src/app/admin/staff/page.tsx`, `src/app/admin/kiosks/page.tsx`, `src/app/teacher/applications/page.tsx`: administrator workflows.
- `src/app/login/page.tsx`, `src/features/kiosk/*`: kiosk family.

### Visual verification

- `tests/e2e/ui-visual.spec.ts`: deterministic viewport, focus, target-size, and screenshot assertions.
- `tests/e2e/ui-visual.spec.ts-snapshots/*`: accepted local browser baselines after concept comparison.
- `.superpowers/sdd/2026-08-22-church-attendance-ui-redesign/fidelity-ledger.md`: temporary concept/render comparison record removed after final review.
